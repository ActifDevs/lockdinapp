## Product State

Lockdin is a Cambridge International AS & A Level revision workspace. The current application supports Supabase-backed account creation and login, atomic onboarding, durable subject selection, hierarchical syllabus browsing, per-user topic progress and notes, revision tasks, past-paper attempt logging, exam-date display, dashboard analytics, progress reporting, a study calendar, client-side reminders, and profile/settings management.

Phase 5 is complete. The frontend now separates loading, empty, error, stale-cache, and retry states; stores selected tabs, views, filters, and calendar context in canonical URL query parameters; scopes notification preferences to the authenticated account in browser storage; and reconciles successful and failed mutations with domain-specific TanStack Query caches.

No privileged SQL introspection was performed during this documentation run.
- Shared reference tables: `subjects`, `syllabus_versions`, `syllabus_units`, `syllabus_topics`, `syllabus_learning_outcomes`, `assessment_components`, and `learning_outcome_components`.
- User-owned tables: `profiles`, `user_subjects`, `topic_progress`, `tasks`, `past_paper_attempts`, and `exam_dates`.
- RLS: enabled by migrations on all six user-owned tables. Direct privileges are deliberately table-specific; some writes are possible only through reviewed functions.

- Runtime connections: serverless Supabase pooler URLs on port 5432 are rejected. Vercel/serverless runtime requires transaction pooling on port 6543; migration tooling prefers `DIRECT_DATABASE_URL` with a direct or session-compatible connection.
- Reference import: repository release evidence records the nine subjects as imported in hosted production. The current run verified the repository data and live DB health, but did not query hosted row counts.

## Known Limitations

1. Validation-only and import dry-run modes perform zero intended database writes but still require a syntactically configured `DATABASE_URL` at shutdown because `pool.end()` forces lazy pool initialization.
2. DB-backed syllabus integration tests require a disposable migrated database; they were not executed in this checkpoint environment.
3. The standalone Python audit command rewrites `_audit_report.json`; it is not a purely no-output read operation even though it never changes CSV source files.
4. Import transactions are per subject, not one transaction across all nine subjects. An error rolls back the current subject, while earlier successful subjects remain committed.
5. Re-import updates/inserts known natural keys and rebuilds outcome/component links, but does not remove every stale unit/topic/outcome/component that disappears from a later CSV.
6. Notification preferences and reminder dedupe markers are browser-local and account-scoped, not server-persisted or cross-device.
7. Exam-date create/delete endpoints exist, but the current calendar is read-only for exam dates.
8. Onboarding draft persistence and broader editing of existing task fields remain deferred.
9. A global canonical `past_papers` catalogue does not exist. Attempts reference shared assessment components and store session/year/variant atomically.
10. `artifacts/mockup-sandbox` remains design tooling in the workspace and is not the deployed product entry point.
