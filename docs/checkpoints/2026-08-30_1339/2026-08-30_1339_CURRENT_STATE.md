## Product State

Lockdin is a Cambridge International AS & A Level revision workspace. It currently supports Supabase-backed signup/login and password recovery, atomic onboarding, durable subject membership, structured intended exam sessions, syllabus and learning-outcome browsing, topic progress/notes, revision tasks, past-paper logging, exam-date display, dashboard/progress analytics, a study calendar, account-scoped browser reminders, and profile/settings management.

Phase 6 adds reliability around changing syllabus editions. Each real subject currently has one published immutable `r001` reference graph. Existing users stay pinned to their stored graph. New memberships supply a year and May/June or Oct/Nov series; server-side database functions select exactly one published, applicable, product-enabled version or fail closed. There is no user-facing version selector and no automatic repin.

## Known Limitations

1. There is no real `r002`; all nine real subject graphs are `r001` only.
2. Feb/Mar automatic assignment is deliberately disabled and deferred.
3. Publishing a draft is implemented, but flipping DEFAULT on an already-published successor requires an explicit owner SQL/admin operation.
4. Existing memberships are never automatically repinned; any remapping requires separate authorization and tooling.
5. `docs/reference-data/syllabus-applicability/README.md` still describes the write-set as not applied, while later Phase 6 closeout evidence records it as applied and verified. That README is stale.
6. The frontend unit suite did not complete on this checkpoint's Windows host; code-identical post-merge evidence records 227/227 passing.
7. Local parallel tests can hit five-second contention; CI explicitly serializes the frontend suite.
8. The disposable database harness requires Docker and an explicit `LOCKDIN_ALLOW_DESTRUCTIVE_LOCAL_DB=1`; it rejects hosted/non-loopback targets.
9. Notification settings are browser-local, exam-date mutation controls are not mounted, onboarding drafts are not persisted, and existing-task editing is limited.
10. No global canonical past-paper catalogue exists; attempts use shared assessment components plus atomic session/year/variant fields.
