## Product State

Lockdin (formerly Scholr) is an intelligent A-Level revision management platform tailored for Cambridge Assessment International Education (CAIE) AS & A-Level students.

The application allows students to:
1. **Authenticate Securely**: Register, log in, manage sessions, update passwords, and handle password resets via Supabase Auth.
2. **Select & Customize Subjects**: Browse the canonical 9-subject A-Level catalogue (Biology, Chemistry, Physics, Mathematics, Further Mathematics, Computer Science, Economics, Business, History) and enroll in personalized subject lists.
3. **Track Topic Progress**: Track mastery across syllabus units, topics, and subtopics with user-owned topic completion states (`not_started`, `in_progress`, `completed`), personal notes, and overall percentage completion overlays.
4. **Manage Revision Tasks**: Create, edit, complete, and organize user-scoped revision tasks tied directly to subjects or specific syllabus topics, featuring priority tags, target completion dates, and completion status.
5. **Log & Analyze Past-Paper Attempts**: Record practice exam performance across atomized components and variants (e.g. `9702/42`), storing exact raw marks, total available marks, calculated percentage scores, session timing (e.g. `May/June 2024`), and completion timestamps.
6. **Set Exam Dates & Track Countdown**: Store and view user-specific upcoming target exam dates per subject with automated countdown timers on the main dashboard.
7. **View Mastered Analytics**: Inspect high-level dashboard summaries, subject mastery cards, score trend charts, and gamified progress indicators tailored strictly to the caller's authenticated user ID.

## Database State

- **Provider**: PostgreSQL hosted on Supabase (Project ID: `hazvcdrcvsxmuwdfiucx`).
- **Migration Chain**: Exactly 10 migrations (`0000_syllabus_reference_and_paper_attempts.sql` through `0009_dear_mathemanic.sql`) recorded in `lib/db/migrations/meta/_journal.json`. Migration `0010` is **ABSENT**.
- **Row Level Security (RLS)**: Active and enforced on all 6 personal user-owned tables (`profiles`, `user_subjects`, `tasks`, `topic_progress`, `past_paper_attempts`, `exam_dates`). Policies restrict SELECT, INSERT, UPDATE, and DELETE strictly to `auth.uid() = user_id`.
- **Shared Reference Data**: 7 immutable reference tables (`subjects`, `syllabus_versions`, `syllabus_units`, `syllabus_topics`, `syllabus_learning_outcomes`, `assessment_components`, `learning_outcome_components`). Free of user-specific state.
- **Connection Model**: API server connects via `DATABASE_URL` (Supabase Session Pooler, port 5432, Node `pg` connection pool with `max: 1` for serverless execution). Drizzle migrations use `DIRECT_DATABASE_URL`.

## Known Limitations

1. **Clean Empty-Database Bootstrap Gap**: A completely empty, freshly provisioned database requires executing the Drizzle migration runner followed by the CLI syllabus importer (`pnpm --filter scripts import-syllabi`) to populate the 9 reference subjects before initial login/signup.
2. **Local Supabase Docker Runner on Windows**: Local integration tests using `supabase start` encounter Docker container health check failures on certain Windows environments due to Supabase Studio container timeouts (historical Phase 3 integration test suite passed 41/41 on the initialized local environment; inability to reproduce locally after loss of the initialized disposable local database is an environment/bootstrap limitation, NOT an application regression). Unit tests (64 API + 88 FE) run headlessly without Docker and pass 100%.
3. **Legacy Teammate Domain**: `https://lockedin-study.vercel.app` is an old teammate-owned preview deployment predating the team migration; the authoritative Production target is `https://lockdinapp-web.vercel.app`.
4. **Canonical Paper Entity Abstraction**: Past-paper logging atomizes paper identity into `subject_code`, `component_number`, `variant_number`, `exam_session`, and `exam_year` directly on `past_paper_attempts`. A centralized global `past_papers` catalogue table remains deferred.
