## Product State

Lockdin (formerly Scholr) is an AI-enhanced study planner and revision tracking web application tailored for Cambridge International A-Level students.

Currently implemented application functionality:

1. **Syllabus Reference Data & Ingestion Pipeline:**
   - 9 Cambridge A-Level syllabi fully supported: Further Mathematics (9231), History (9489), Business (9609), Computer Science (9618), Biology (9700), Chemistry (9701), Physics (9702), Economics (9708), and Mathematics (9709).
   - Standardized 12-column CSV structure parsed, validated, and normalized into a hierarchical structure (`subjects` → `syllabus_versions` → `syllabus_units` → `syllabus_topics` → `syllabus_learning_outcomes`).
   - Atomized assessment components (`assessment_components`) linked via junction table `learning_outcome_components`.

2. **API Services (`artifacts/api-server`):**
   - Express server mounted under `/api` running on port 3001.
   - Live DB-backed endpoints:
     - `GET /api/healthz` → `{"status":"ok"}`
     - `GET /api/subjects` → returns 9 database-backed subjects with calculated live topic counts matching database rows (e.g., 24 for 9231, 81 for 9489, 34 for 9609, 45 for 9618, 62 for 9700, 104 for 9701, 81 for 9702, 51 for 9708, 38 for 9709).
     - Additional endpoints for syllabus units/topics, task management, exam dates, progress updates, and past paper logging.

3. **Frontend Platform (`artifacts/revision-platform` & `artifacts/mockup-sandbox`):**
   - Single-page application built with React 19, Vite 7, TailwindCSS v4, Framer Motion, and Wouter routing.
   - Interactive subject selection, syllabus topic navigation, task creation modal, past paper attempt logger, exam countdown widget, and revision progress dashboard.
   - Client-side mock user authentication storing user state in `localStorage`.

## Known Limitations

1. **Lack of Real Authentication & RLS:** Current database tables lack `user_id` columns and Row Level Security (RLS) policies. User-created data (`tasks`, `past_paper_attempts`) currently shares a single database namespace.
2. **Delete-and-Reinsert Junction Churn:** Re-running `syllabus:import` clears and re-inserts `learning_outcome_components` rows inside a transaction. While final row counts remain completely stable (4,817 rows), write reporting shows per-run creation rather than pure differential patch operations. This is non-blocking for Phase 1 completion.
3. **Direct Database Host IPv6 Requirement:** Direct PostgreSQL connection (`db.<ref>.supabase.co:5432`) is IPv6-only on standard Supabase free tier networking. Node.js applications must connect via the session pooler (`*.pooler.supabase.com:5432`) on IPv4.
4. **Hardcoded Fallback Catalog:** `artifacts/revision-platform/src/lib/syllabus-data.ts` maintains an offline fallback subject catalog (`SUBJECT_CATALOG`) for offline rendering.
