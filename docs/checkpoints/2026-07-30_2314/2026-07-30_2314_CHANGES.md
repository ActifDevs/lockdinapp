## Technical Debt

### Non-Blocking Technical Debt (Recorded for Future Phases)

#### 1. Learning Outcome Components Synchronization

**Debt:** `learning_outcome_components` currently uses delete-and-reinsert synchronization during repeated imports
**Impact:** Final data remains stable, but relationship reporting is not fully differential
**Status:** Non-blocking for Phase 1 completion
**Required:** Consider differential sync implementation in future phase if needed
**Notes:** While final row counts remain completely stable (4,817 rows), write reporting shows per-run creation rather than pure differential patch operations. This does not affect data integrity but could be optimized for better reporting.

#### 2. Database Module Eager Import

**Debt:** Validation and dry-run currently require DATABASE_URL to be loaded because the database module is imported eagerly, even though dry-run performs zero writes
**Impact:** Cannot run validation or dry-run without database connection, even for purely structural checks
**Status:** Non-blocking for Phase 1 completion
**Required:** Consider lazy database module loading in future phase if needed
**Notes:** The database module is imported at module load time, which requires DATABASE_URL to be set even for operations that don't touch the database (like validation or dry-run). This is a minor inconvenience but does not block Phase 1 completion.

#### 3. Empty-Database Baseline Migration

**Debt:** The initial migration (0000_syllabus_reference_and_paper_attempts.sql) was applied via hand-bootstrap SQL editor rather than through a clean empty-database baseline
**Impact:** Migration history does not reflect a pristine initial state; future schema evolution may require manual intervention
**Status:** Non-blocking for Phase 1 completion
**Required:** Consider establishing a clean empty-database baseline migration in future phase if needed
**Notes:** The migration was hand-edited and applied manually to an existing database state. While the current schema is functional, the migration journal does not represent a clean evolution from an empty database.
