# Data Pipeline & Ingestion Architecture

## Overview

The reference data pipeline transforms authoritative Cambridge Assessment International Education (CAIE) syllabus documents into structured, normalized relational data in PostgreSQL.

```text
Official CAIE Syllabus PDFs
  ↓ (Extraction & Verification)
Validated CSV Files (data/syllabi/raw/)
  ↓ (Audit & Validation Script: docs/audit_syllabi_v2.py)
Audit Verification Reports (data/syllabi/raw/_audit_report.json)
  ↓ (Ingestion Engine: scripts/src/syllabus/)
Database Upsert & Normalization (lib/db)
  ↓ (PostgreSQL Shared Reference Tables)
Express API Server Endpoints (/api/subjects, /api/subjects/:id/syllabus)
  ↓ (JSON Response)
React Revision Platform Client Application
```

## CSV Schema Specification

Every validated syllabus CSV file contains exactly 12 standard column headers:

1. `Main Topic`: High-level syllabus unit or module name (e.g. `1 Physical quantities and units`).
2. `Subtopic`: Specific section within the main topic (e.g. `1.1 Physical quantities`).
3. `Learning Outcome`: Concrete numbered or bulleted learning objective.
4. `Subject`: Full official subject title (e.g. `Physics`).
5. `Exam Board`: Standardized as `Cambridge Assessment International Education`.
6. `Qualification`: Standardized as `Cambridge International AS & A Level`.
7. `Level`: Level indicator (`AS Level` or `A Level`).
8. `Component Name`: Assessment component title (e.g. `Paper 1 Multiple Choice`, `Paper 4 A Level Structured Questions`).
9. `Paper Code`: Official paper notation (e.g. `9702/1`, `9702/4`).
10. `Duration (min)`: Exam duration in minutes (e.g. `75`, `120`).
11. `Total Marks`: Maximum achievable raw marks (e.g. `40`, `100`).
12. `Weighting (%)`: Assessment weighting percentage (e.g. `31`, `38`).

## CSV → Database Normalization Mapping

The ingestion engine in `scripts/src/syllabus/` normalizes flat CSV rows into 7 relational database tables:

| CSV Column | Destination Table | Destination Column | Processing & Transformation Notes |
| --- | --- | --- | --- |
| `Subject` | `subjects` | `name` | Extracted and upserted uniquely by `code`. |
| `Paper Code` (prefix) | `subjects` | `code` | Extracted from prefix (e.g. `9702` from `9702/1`). |
| `Exam Board` | `subjects` | `exam_board` | Preserved verbatim (`Cambridge Assessment International Education`). |
| `Qualification` | `subjects` | `qualification` | Preserved verbatim (`Cambridge International AS & A Level`). |
| `Subject` + Year Range | `syllabus_versions` | `version_code`, `valid_from_year`, `valid_to_year` | Version record linked to subject (e.g. `9702-2022-2024`). |
| `Main Topic` | `syllabus_units` | `unit_number`, `title` | Parsed prefix becomes `unit_number`; remainder becomes `title`. |
| `Subtopic` | `syllabus_topics` | `topic_number`, `title` | Parsed prefix becomes `topic_number`; linked to parent unit. |
| `Learning Outcome` | `syllabus_learning_outcomes` | `outcome_number`, `description` | Parsed index becomes `outcome_number`; full text stored in `description`. |
| `Component Name` | `assessment_components` | `name` | Official component title (e.g. `Paper 4 A Level Structured Questions`). |
| `Paper Code` | `assessment_components` | `component_number`, `code` | Parsed component integer (e.g. `4`) and full code (`9702/4`). |
| `Level` | `assessment_components` | `level` | Enum value: `'AS Level'` or `'A Level'`. |
| `Duration (min)` | `assessment_components` | `duration_minutes` | Parsed integer. |
| `Total Marks` | `assessment_components` | `total_marks` | Parsed integer. |
| `Weighting (%)` | `assessment_components` | `weighting_percentage` | Parsed integer / numeric. |
| Row Co-occurrence | `learning_outcome_components` | `learning_outcome_id`, `component_id` | Junction mapping linking each outcome to tested assessment components. |

## Ingestion Commands

The syllabus import pipeline is executed via the `scripts` package CLI:

### 1. CSV Validation Audit
Run the standalone Python audit tool to verify CSV integrity and header conformance:
```bash
python docs/audit_syllabi_v2.py
```

### 2. Importer Dry-Run Mode
Simulate ingestion and validate CSV files without committing changes to PostgreSQL:
```bash
pnpm --filter scripts import-syllabi --dry-run
```

### 3. Real Database Import
Perform an idempotent transactional import into the database:
```bash
pnpm --filter scripts import-syllabi
```

### 4. Single Subject Import
Import or update a specific subject by its subject code:
```bash
pnpm --filter scripts import-syllabi --subject 9702
```

## Ingestion Safety & Integrity Guarantees

1. **Transaction Isolation**: All database operations for a subject are executed within a single PostgreSQL transaction (`db.transaction(...)`). If any error occurs, all partial mutations are rolled back automatically.
2. **Idempotency**: All entity insertions utilize Drizzle's `onConflictDoUpdate` or unique natural key lookups:
   - `subjects`: Unique on `code`.
   - `syllabus_versions`: Unique on `(subject_id, version_code)`.
   - `syllabus_units`: Unique on `(version_id, unit_number)`.
   - `syllabus_topics`: Unique on `(unit_id, topic_number)`.
   - `assessment_components`: Unique on `(subject_id, component_number, level)`.
   - Re-running the importer produces zero duplicate records and does not break foreign keys.
3. **Hierarchy & Ordering Preservation**: Sequential integer fields (`unit_number`, `topic_number`, `outcome_number`) are parsed and preserved from the source text, maintaining exact curriculum sequencing.
4. **Data Isolation**: The importer mutates shared reference data tables only. It never accesses or modifies user-owned tables (`profiles`, `user_subjects`, `tasks`, `topic_progress`, `past_paper_attempts`, `exam_dates`).

## Runtime Data Flow

How shared reference data reaches the student's browser:

1. **Catalogue Exploration**: The frontend calls `GET /api/subjects` (public). The backend queries `subjectsTable` and returns the canonical 9 subjects.
2. **Subject Selection**: When a student enrolls, the client calls `POST /api/user-subjects` (authenticated). The backend creates a record in `user_subjects` referencing `subjects.id` under `req.userId`.
3. **Syllabus Rendering**:
   - The student navigates to a subject view (`/subjects/:id`).
   - The frontend calls `GET /api/subjects/:id/syllabus` (optional auth).
   - The backend retrieves the active `syllabus_versions`, `syllabus_units`, `syllabus_topics`, and `syllabus_learning_outcomes`.
   - If the request includes a valid Bearer JWT, the backend performs a left-join overlay with `topic_progress` for the caller's `req.userId`.
   - The client renders the complete curriculum tree with the student's personalized mastery checkboxes and study notes.
