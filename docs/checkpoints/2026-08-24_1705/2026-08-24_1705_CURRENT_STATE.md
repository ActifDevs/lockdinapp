## Product State

Lockdin (formerly Scholr) is an intelligent revision management and exam preparation platform designed specifically for Cambridge Assessment International Education (CAIE) AS & A-Level students.

The application currently provides the following functional capabilities:

1. **Authentication & Session Management**: Complete student identity lifecycle backed by Supabase Auth, including sign-up, sign-in, password reset, update password, session refresh, and bearer token verification.
2. **Subject Catalogue & Enrollment**: Canonical 9-subject Cambridge catalogue (Biology, Chemistry, Physics, Mathematics, Further Mathematics, Computer Science, Economics, Business, History). Students enroll in personalized subject selections persisted in `user_subjects`.
3. **Syllabus Navigation & Mastery Tracking**: Hierarchical exploration of syllabus units, topics, subtopics, and learning outcomes loaded from shared reference tables. Personal mastery states (`not_started`, `in_progress`, `completed`) and student notes are stored per-user in `topic_progress` and dynamically overlaid.
4. **Revision Task Management**: Full CRUD operations for user-owned revision tasks in `tasks`, linked optionally to subjects and syllabus topics, featuring priority levels (`low`, `medium`, `high`), target due dates, and completion toggles.
5. **Past-Paper Attempt Logging & Scoring**: Structured logging of exam practice in `past_paper_attempts`. Paper identity is atomized by subject code, component number, variant number, exam session (`May/June`, `Oct/Nov`, `Feb/Mar`, `Specimen`), and year. Automatically computes raw marks, percentage scores, and time taken.
6. **Target Exam Dates & Countdowns**: User-specific exam schedules stored in `exam_dates` with real-time countdown widgets on the dashboard.
7. **Personalized Analytics & Dashboard**: Authenticated `/api/dashboard/summary` endpoint rendering subject mastery grids, score trend line charts, recent activity streams, and gamified progress indicators scoped strictly to the caller's `auth.uid()`.
8. **Server-Authoritative Request Tracing**: End-to-end request correlation with server-generated UUIDs emitted in `X-Request-Id` response headers and correlated with structured Pino logs.

- **Connection Model**: API server connects via `DATABASE_URL` (Supabase Session Pooler, port 5432, Node `pg` connection pool with `max: 1` for serverless execution). Drizzle migrations use `DIRECT_DATABASE_URL`.

## Known Limitations

1. **Clean Empty-Database Bootstrap Gap**: A completely empty, freshly provisioned database requires executing the Drizzle migration runner followed by the CLI syllabus importer (`pnpm --filter scripts import-syllabi`) to populate the 9 reference subjects before initial login/signup.
2. **Local Supabase Docker Runner on Windows**: Local integration tests using `supabase start` require an active Docker engine; when Docker Desktop is unavailable, integration tests cannot be run locally (safety guard prevents hitting hosted databases). Monorepo unit test suites (107 API + 88 FE = 195 tests) run headlessly without Docker and pass 100%.
3. **Frontend Auth Cutover (Phase 5)**: Frontend client components still maintain legacy auth fallback code paths that will be streamlined in Phase 5.
4. **Canonical Paper Entity Abstraction**: Past-paper logging atomizes paper identity into `subject_code`, `component_number`, `variant_number`, `exam_session`, and `exam_year` directly on `past_paper_attempts`. A centralized global `past_papers` catalogue table remains deferred.

- **Fail-Secure Global Auth**: New endpoints mounted under `/api` automatically require authentication unless an explicit exception is reviewed and registered in `global-auth-policy.ts`.
