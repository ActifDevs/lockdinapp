| Learning Outcome | (NOT IMPLEMENTED) | Would require `syllabus_learning_outcomes` table |
| Exam Board | (NOT IMPLEMENTED) | Metadata only, not stored in current schema |
| Qualification | (NOT IMPLEMENTED) | Metadata only, not stored in current schema |
| Level | (NOT IMPLEMENTED) | Would require component/variant tables |
| Component Name | (NOT IMPLEMENTED) | Would require `assessment_components` table |
| Paper Code | (NOT IMPLEMENTED) | Would require component/variant tables |
| Duration (min) | (NOT IMPLEMENTED) | Would require `assessment_components` table |
| Total Marks | (NOT IMPLEMENTED) | Would require `assessment_components` table |
| Weighting (%) | (NOT IMPLEMENTED) | Would require `assessment_components` table |

### Mapping Limitations
**Current Schema Gaps:**
1. **No learning outcomes storage:** CSV has learning outcomes but no table to store them
2. **No assessment components:** Paper codes, duration, marks, weighting cannot be stored
3. **No syllabus versioning:** Cannot track changes to syllabus over time
4. **No component/variant atomization:** Paper codes stored as strings, not decomposed
5. **No metadata storage:** Exam board, qualification, level information lost

**Data Loss:**
- Learning outcomes (present in CSV, nowhere to store)
- Assessment component details (paper codes, duration, marks, weighting)
- Syllabus metadata (exam board, qualification, level)
- Component/variant relationships
