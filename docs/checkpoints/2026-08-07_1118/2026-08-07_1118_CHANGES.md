### 3. Atomic Onboarding RPC (`lockdin_complete_onboarding`)
- **Previous State:** Onboarding steps were client-driven and non-atomic.
- **Current State:** Implemented database function `lockdin_complete_onboarding` running under `SECURITY DEFINER`. Derives caller exclusively from `auth.uid()`. Validates input strings and subject selection (1–3 subjects), updates profile (`full_name`, `username`, `level`, `exam_session`, `onboarded_at`), and creates initial starter tasks in a single PostgreSQL transaction.
- **Reason:** Ensure onboarding operations are tamper-proof and fully atomic.

### 4. User Task Ownership & Row Level Security (RLS)
- **Previous State:** `tasks` table lacked a `user_id` column; all tasks existed in a shared global namespace.
- **Current State:** Added `user_id` `uuid NOT NULL` column to `tasks` referencing `auth.users(id)`. Enabled Row Level Security (RLS) on `tasks` and `profiles`. Configured policies `tasks_select_own`, `tasks_insert_own`, `tasks_update_own`, `tasks_delete_own` restricting operations to `auth.uid() = user_id`. Implemented strict privilege baselines (`REVOKE ALL PRIVILEGES FROM PUBLIC, anon, authenticated`).
- **Reason:** Prevent cross-user data leakage and enforce strict user data isolation.
- **Files Affected:**
  - [lib/db/src/schema/tasks.ts](file:///c:/Users/emman/Documents/lockdinapp/lib/db/src/schema/tasks.ts)
  - [lib/db/migrations/0001_chilly_randall_flagg.sql](file:///c:/Users/emman/Documents/lockdinapp/lib/db/migrations/0001_chilly_randall_flagg.sql)
  - [lib/db/migrations/0003_stormy_mongu.sql](file:///c:/Users/emman/Documents/lockdinapp/lib/db/migrations/0003_stormy_mongu.sql)
- **Database Impact:** `tasks.user_id` is now mandatory (`NOT NULL`). Direct unauthorized access attempts return RLS errors or 0 rows.
- **User-Facing Impact:** Students see only their own revision tasks.

### 5. Authenticated Express API Middleware (`requireAuth`)
- **Previous State:** Express API routes accepted all requests without credential checks.
- **Current State:** Implemented `requireAuth` middleware in `artifacts/api-server`. Verifies Bearer JWT tokens using Supabase verifier client, checks valid UUID `sub` claims, attaches `req.userId` and `req.accessToken` to Express request objects, and instantiates request-scoped Supabase client. Returns HTTP 401 Unauthorized for missing/invalid tokens.
- **Reason:** Protect API routes at the application layer and propagate caller identity down to database connections.
- **Files Affected:**
  - [artifacts/api-server/src/middlewares/require-auth.ts](file:///c:/Users/emman/Documents/lockdinapp/artifacts/api-server/src/middlewares/require-auth.ts)
  - [artifacts/api-server/src/routes/tasks.ts](file:///c:/Users/emman/Documents/lockdinapp/artifacts/api-server/src/routes/tasks.ts)
  - [artifacts/api-server/src/routes/profile.ts](file:///c:/Users/emman/Documents/lockdinapp/artifacts/api-server/src/routes/profile.ts)
- **Database Impact:** API requests query PostgreSQL using caller's JWT token context.
- **User-Facing Impact:** Unauthenticated requests to `/api/tasks` or `/api/profile` receive 401 Unauthorized responses.
