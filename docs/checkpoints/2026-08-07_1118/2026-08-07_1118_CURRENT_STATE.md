## Product State

Lockdin (formerly Scholr) is an AI-enhanced study planner and revision tracking web application tailored for Cambridge International A-Level students.

Currently implemented application functionality:

1. **Supabase Authentication & Identity Lifecycle:**
   - Email/password user signup (`/signup`) with automatic metadata handling.
   - User authentication & session persistence (`/login`, `/auth/callback`, `AuthProvider`).
   - Secure password reset flow (`/forgot-password`, `/update-password`).
   - Automatic database profile creation via PostgreSQL trigger `lockdin_handle_new_user` on `auth.users` insert.
   - Interactive onboarding flow (`/onboarding`) invoking atomic RPC `lockdin_complete_onboarding` to set profile fields and create initial starter tasks.
   - Config-gated Google OAuth support (`VITE_ENABLE_GOOGLE_AUTH`).

2. **User-Owned Task Management:**
   - Fully isolated, multi-tenant user tasks backed by `tasks.user_id` FK to `auth.users(id)`.
   - Complete CRUD operations available in Express API (`/api/tasks`) authenticated via JWT Bearer headers.
   - Ownership enforcement guaranteed at both database level (Row Level Security) and application middleware level (`requireAuth`).

3. **Syllabus Reference Data & Ingestion Pipeline:**
   - 9 Cambridge A-Level syllabi fully supported: Further Mathematics (9231), History (9489), Business (9609), Computer Science (9618), Biology (9700), Chemistry (9701), Physics (9702), Economics (9708), and Mathematics (9709).
   - Normalized relational hierarchy (`subjects` → `syllabus_versions` → `syllabus_units` → `syllabus_topics` → `syllabus_learning_outcomes`).
   - Atomized assessment components (`assessment_components`) linked via junction table `learning_outcome_components`.

4. **API Services (`artifacts/api-server`):**
   - Express server mounted under `/api`.
   - Verified endpoints:
     - `GET /api/healthz` → `{"status":"ok"}`
     - `GET /api/healthz/db` → `{"status":"ok","database":"ok"}`
     - `GET /api/subjects` → 9 DB-backed subjects with topic counts.
     - `GET /api/tasks`, `POST /api/tasks`, `PATCH /api/tasks/:id`, `DELETE /api/tasks/:id` → User-isolated task operations.
     - `GET /api/profile`, `PATCH /api/profile`, `POST /api/profile/onboarding` → User profile and onboarding.
     - Endpoints for exam dates, progress, and past-paper logging.

5. **Frontend Platform (`artifacts/revision-platform`):**
   - Built with React 19, Vite 7, TailwindCSS v4, Framer Motion, and Wouter.
   - Complete authentication views and protected route enforcement (`RequireAuth`, `RedirectIfAuthenticated`).
   - Dynamic subject selection, dashboard metrics, past paper attempt logging, and task planning.

## Database State

- **Provider:** Supabase PostgreSQL.
- **Connection Strategy:** Node.js clients connect over IPv4 using the Supabase Session Pooler (`*.pooler.supabase.com:5432`) with `DATABASE_URL`.
- **Serverless Configuration:** `pg.Pool` settings set to `max: 1`, `idleTimeoutMillis: 5000`, `connectionTimeoutMillis: 10000`, and `allowExitOnIdle: true`.
- **Migration Status:** Schema applied up to migration `0003_stormy_mongu.sql`; Drizzle migration journal (`drizzle.__drizzle_migrations`) fully reconciled with hashes.
- **Table & Policy Summary:**
  - **`profiles`:** Primary key `id` (FK to `auth.users.id`). RLS enabled (`profiles_select_own`, `profiles_update_own`). Explicit `REVOKE ALL FROM PUBLIC, anon, authenticated` baseline with column-level UPDATE grants on `full_name`, `level`, `exam_session`.
  - **`tasks`:** Primary key `id`, column `user_id` `uuid NOT NULL` (FK to `auth.users.id`). RLS enabled (`tasks_select_own`, `tasks_insert_own`, `tasks_update_own`, `tasks_delete_own`). Explicit `REVOKE ALL FROM PUBLIC, anon, authenticated` baseline with table/sequence grants to `authenticated`.
  - **Shared Reference Tables:** `subjects`, `syllabus_versions`, `syllabus_units`, `syllabus_topics`, `syllabus_learning_outcomes`, `assessment_components`, `learning_outcome_components`.
  - **Shared / Operational Tables:** `past_paper_attempts`, `exam_dates` (Phase 3 multi-tenancy target).

## Known Limitations

1. **Phase 3 Multi-Tenancy Scoping Pending:** `past_paper_attempts`, `user_subjects`, and `exam_dates` remain shared database tables; per-user ownership and RLS for these models will be implemented in Phase 3.
2. **Direct Database Host IPv6 Requirement:** Direct PostgreSQL connection (`db.<ref>.supabase.co:5432`) is IPv6-only on standard Supabase free tier networking. Node.js applications connect via the session pooler (`*.pooler.supabase.com:5432`) on IPv4.
3. **Hardcoded Fallback Catalog:** `artifacts/revision-platform/src/lib/syllabus-data.ts` maintains an offline fallback subject catalog (`SUBJECT_CATALOG`) for offline rendering fallback.
